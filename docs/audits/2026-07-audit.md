# Vidya ERP — Forensic Code Audit (2026-07)

**Method:** Verified against actual code only — module `definition.ts` route specs
vs. Next.js App Router `route.ts` files, `navConfig.ts`, Drizzle schema vs. migration
SQL, per-handler scope calls, and a live run of the full test suite. No plan docs,
ledgers, or "done" markers were consulted.

**Caveat on the DB check:** the docker stack was already running (postgres/redis/minio,
an active dev environment, not a fresh boot). It was not torn down to test a literal cold
`docker compose up`. Migration state was verified against the running DB and the migration
SQL read statically. Up-migrations are clean; the rollback path has a real bug (see identity).

## Headline

**4 of 15 modules pass all six checks. 11 do not.** The dominant defect is a class of
**orphaned routes**: handlers that are fully written, unit-tested, composed into the runtime,
and backed by applied DB migrations — but have **no `route.ts` file**, so they 404 in the
actual app. This affects **4 modules across 16 endpoints**, and in two cases the dead
endpoints are wired to buttons on shipping admin screens. No test layer catches this because
**every test layer bypasses Next.js routing** (unit tests call handlers directly; the
integration harness calls module factories directly; `seed-demo.ts` dispatches through an
in-process `call()` shim). There is no Playwright/e2e layer.

## Central facts

- **Unit tests** (`pnpm test`): 67 files, **617 passed, 0 failed**.
- **Integration tests** (`pnpm test:integration`, live Postgres/Redis/MinIO): **71 passed, 3 failed** —
  - `migrations.int.test.ts` ×2: rolling back `identity/0002_student_role` aborts on a
    Postgres check-constraint violation, plus the consequent idempotency assertion.
  - `heartbeat-job.int.test.ts` ×1: a Prometheus counter assertion reads `undefined`.
- **Migrations**: `pnpm db:status` → **26 applied, 0 pending**. Up-migrations clean; the
  identity rollback bug only bites `db:rollback`.

## The orphaned-route defect (16 endpoints)

- **exams — all 7:** `series` (POST/GET), `series/{seriesId}` (DELETE), `slots` (POST),
  `slots/{slotId}` (DELETE), `classes/{classId}/schedule` (GET), `my-schedule` (GET).
  The entire `/manage/exams` admin page is non-functional.
- **leave — all 4:** `requests` (POST), `mine` (GET), `pending` (GET),
  `requests/{requestId}/decide` (POST). The entire `/manage/leave` page is non-functional.
- **identity — 1, actively breaking UI:** `identity.password-set`
  (POST `/api/v1/identity/users/{userId}/password`). The "Set password" button on
  `/manage/users` 404s.
- **people — 4, actively breaking UI:** `document-upload`, `document-list`,
  `document-download`, `document-delete`. `/manage/directory` calls `docList` and
  `docDownloadUrl` — both 404.

## Other cross-cutting findings

- **Two scope patterns coexist.** Shared platform `ScopeChecker` (`checkScope(deps.scopeChecker, …)`)
  in academics, syllabus, people, identity, coursework, analytics, reporting, fees.
  **exams, leave, results, notices hand-roll** college/dept containment. **Timetable is the real gap**:
  `periods-get`, `periods-set`, `entry-create`, `entry-delete` do no per-record check — only the
  coarse `ADMIN_ONLY` role gate, so an admin from one college can edit another's timetable. The one
  timetable handler that does check (`section-grid`) is untested.
- **`navConfig.ts` role bug.** `const ALL` lists 5 roles; the enum
  (`platform/src/auth/types.ts`) has 7 (`+student, +accountant`). Every `roles: ALL` entry is
  invisible to accountant and student. An accountant has no UI path to reporting at all.
- **Analytics dashboard shows no data in a demo.** Dashboard/at-risk/rollup read precomputed
  rollup tables; `seed-demo.ts` never calls `analytics.recompute`. No recompute UI trigger either.
- **Reporting's hall-ticket has no live data source** — exam series/slots can only be created via
  the routeless exams UI.
- **Integration coverage thin.** fees, notices, results, exams, leave, coursework have none.
